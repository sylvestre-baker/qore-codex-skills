Plan a change, challenge a specification or check a real web flow with Codex. Keep three reusable methods, then adapt them to the rules of each project.

A skill is a set of instructions and local checks that Codex follows. Qore supplies the methods; your project supplies the commands, rules and web entry they must use.

What changes in practice?

Project rule: “Reach Back using the keyboard and check the returned focus.”

Plan
Turn that rule into separate acceptance checks for keyboard access, the returned screen and focus.
Review
Challenge evidence that only shows a mouse click: it cannot establish keyboard access.
UX review
Use Tab, press Enter, then observe the introduction and the focused heading in the browser.

Technical details: generate the three skill folders 
python3 tools/qore.py derive \
  --profile profiles/qaizen-labs.json \
  --project-root examples/qaizen-labs \
  --output /tmp/qore-labs-new
python3 tools/qore.py verify /tmp/qore-labs-new

Run from a checkout of version 0.2.1, using an unused output path. Python 3 is required. The assembler validates data; it does not execute profile commands or grant permission. Changed source files invalidate the affected profile facts; generate a refreshed version in new staging and inspect the diff.

One existing project

Can the Labs journey really be checked with a keyboard?

Qaizen Labs already has a public readiness flow. An earlier protocol could accept a mouse click on Back as evidence of a keyboard check. That was a gap in our verification protocol, not a proven bug in the website.

Question: what evidence would establish that a person can open help and return to the introduction using the keyboard, without answering? All three methods were used on this case; each has its own output and evidence.

01 / Plan

Make the distinction explicit

Five perspectives and cross-examination produced a sourced specification. Back reachability, Close focus and the unanswered state have separate acceptance signals.

Review the public Qore helpers

Three finders and a separate verifier ran in an isolated Linux environment. Four distinct coordination problems were reproduced; original findings and post-fix checks are retained separately.

Exercise the real entry and return

The observed desktop flow follows the real Labs control, opens help with keyboard input, closes it, reaches Back by sequential Tab and returns to the introduction without answering a question.

Where this evidence stops

Browser observations cover one dated desktop English entry/state flow. They do not certify accessibility conformance, performance, every question, native apps or future deployments. Linux qualification ran without a browser driver; browser tests skipped there are not passes.

Agent Mail is optional. Separate sessions communicate through actual messages, while an operator starts or resumes bounded work turns. There is no automatic wakeup claim. Cooperative session identity is not cryptographic isolation. The persistent dependency recommendation remains partial.

No external human first-use trial was observed. No Ambassador admission, endorsement or comparative improvement is claimed. Private website source, raw mail logs, credentials and raw browser traces are excluded.

Use the method your task needs

Qore is for developers already using Codex. These skills are independent; ordinary small changes may only need repository instructions or a direct check. Use your host’s routine code-review workflow for ordinary Git diff review.
