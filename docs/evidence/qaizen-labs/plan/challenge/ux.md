## Challenge QA: prove states separately and keep controls discriminating

**Target: L04 matrix.** Correct Close focus and Back focus do not alone prove every declared help transition. Current actions assert the first Enter opens and Space closes, but do not assert reopened state before traversing to Close (`browser-actions.json:37-78`). If a hidden/faulty Close remained reachable, final closure and summary focus would not distinguish a failed reopen. Add an explicit reopened-open assertion and retain an open-state capture or equivalent observed attribute event. A negative control with wrong Close focus while Back remains correct, proposed by QA, is useful and should remain separate from Back's negative control.

**Target: unanswered proof.** Support QA's pre-Back unchecked check. In my Analyze report I requested both “after Close” and “immediately before Back”; these can be one assertion while still in the first-question state, before traversal begins. This avoids redundant actions and the 40-step action limit (`browser_probe.mjs:23`). A final intro-only check can be vacuous after controls unmount. A positive answer-presence/unchecked check plus a counterexample selecting an answer before Back discriminates that gap. Endpoint checks do not prove that no transient selection ever occurred; report that limit rather than introducing continuous monitoring without evidence.

**Target: timing risk.** Agree with delayed-focus and never-focus controls, but narrow the claim: each keyboard action already receives 900 ms before the next action (`browser_probe.mjs:114,142-143`). A frame-delayed restoration will often already succeed; the discriminating positive delay must exceed that fixed pause while remaining within the declared assertion timeout. URL already waits finitely (`:116`); do not rewrite it as missing functionality. Poll the expected condition without pressing Enter again. Eventual focus is a proposed observation contract, not an established website timing guarantee.

Keep the finite bound, initial focus and complete step sequence. Failure means the target was not reached in that run. Shift+Tab is contract-permitted (`surface-contract.json:15`; checker `:35`) but a separately declared alternative run must retain the original failed forward traversal; it cannot silently rescue it.
- **QA's stable-state and answer-boundary questions:** no precise public selectors are established by this snapshot. Use the same observed introduction predicate before/after the journey, plus question absence. Retain the current conservative global selection predicate until an observed unrelated selected UI provides a reason for an additive questionnaire-scoped assertion (`browser_probe.mjs:124-125`). Do not narrow it merely because a hypothetical selected navigation tab exists.
- **Artifact completeness:** support QA's enclosing identity manifest and Architecture's small evidence table. Generic probe COMPLETE remains execution status. A missing optional video/trace need not automatically invalidate independently complete assertions and inspected screenshots; the lead must name required artifacts and missing capability explicitly. Trace privacy remains a canary-test hypothesis, so avoid a whole-artifact “no headers/bodies retained” guarantee until checked (`browser_probe.mjs:37,67,155`).
- **Product/Delivery boundaries:** accept separate local-correction and current-site-observation gates. No site defect, certification or broader entry keyboard coverage is inferred. Entry and Start remain click actions in this scoped journey (`surface-contract.json:9-10`).
