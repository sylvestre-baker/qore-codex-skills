# Qore Skills 0.3.0: scope and verification

This release brings together recoverable installation, two reproducible Qodo lessons, and a bounded specialization diagnostic. It updates the three local skills, package metadata, download instructions and static showcase. It introduces no account, hosted backend or automatic client migration.

## Included behavior

- The installer validates private staging, creates destinations without overwriting existing work, verifies installed bytes and cleans up only unchanged attempt-owned paths after handled errors. Uncertainty is preserved in actionable recovery diagnostics. No crash, hostile-concurrency or atomic-three-folder guarantee is made.
- The recovery replay checks the actual before/after cases and rejects unsafe diagnostic retry advice before reporting PASS. The [recovery case](../evidence/install-recovery/README.md) preserves Qodo input, classifications, independent counterexamples and correction identities.
- The [earlier Qodo walkthrough](../tutorials/qodo-review.md) remains a separate historical validator/profile case. Its source snapshots and fixtures are not silently replaced by the current helper.
- The optional [specialization diagnostic](../evidence/specialization/README.md) retains all 18 original attempts: 14 COMPLETE and 4 PARTIAL after independent qualification. Missing required browser observations remain missing. There is no comparative winner, measured saving or general superiority claim.
- The sourced Labs profile preserves forward Tab; profile consumers, browser locators, qualification summaries and bounded lifecycle reporting include their targeted corrections.

## What release checks establish

Fresh checks exercise current contracts, package integrity, reproducible full/compact builds, generic and derived installation, refusal paths, both Qodo replays, profile preflights, exported evaluation records and static-site closure. Existing optional Chromium tests use local synthetic fixtures when that driver is explicitly available. Recorded agent and browser executions keep their original candidate identities; this release does not relabel them as fresh 0.3.0 campaigns.

The [0.3.0 release assets](https://github.com/sylvestre-baker/qore-codex-skills/releases/tag/v0.3.0) carry exact archive checksums and the final release verification receipt. That receipt identifies the released source commit, actual commands, counts and limits. GitHub Actions records the merged source and Pages publication separately. A successful build alone is neither a deployed site nor a proof of reasoning quality.

The pinned offline recovery runtime remains an exact subset of c3ce75c at version 0.2.1. The current package helper is version 0.3.0 and also includes later packaging changes. Historical receipts are evidence for their named snapshots, not byte-identity claims about the current helper.

## Update without losing adaptations

Keep the current installation. Build or extract a new candidate, verify it, compare it with the target and inspect the diff. Use a new staging or target path: installation never automatically replaces local skills. Refresh stale project sources and regenerate derivatives before claiming current coverage. See [safe updates](../profiles.md#update-without-overwriting) and [installation recovery](../../INSTALL.md).

External human first use and applicant listening remain NOT_OBSERVED. The historical cookie-banner implementation is private, local and outside this repository's publication. No employer/provider endorsement or Ambassador submission follows from a release.

Historical evaluation reconstruction reads the frozen builder's literal version without importing or executing its Python code. Current release metadata cannot rewrite an old worker manifest. Regression controls cover generic and derived reconstruction after a version change, plus refusal of executable version expressions.
